# V2 Database Import Contract

## 1. Purpose

V2 treats the CRM database as the source of truth. Import work must prove that a row has a clear organization, canonical parent, external identity, and review trail before it can enter Clients, Sites, Jobs, Documents, or linked communication records.

This contract is for readiness and validation only. It does not authorize a real import, V1 migration apply, provider sync, Drive crawl, mailbox crawl, or report generation.

## 2. Core Relationship Model

Every CRM row belongs to exactly one organization. The core business chain is:

```text
organizations -> clients -> sites -> jobs -> reports
                         -> bmp_systems -> observations
                         -> evidence_files
                         -> reminders
                         -> email_messages / ai_drafts
```

Required relationship rules:

- Sites must have a client.
- Jobs must have a client and a site.
- A job site must belong to the same client as the job.
- Evidence files and Drive links must attach to exactly one clear parent for import review.
- Emails may remain unlinked only when marked as explicitly unlinked for review.
- External IDs must be stored separately from canonical V2 IDs so re-runs can detect duplicates.

## 3. Table-By-Table Summary

| Table | Role | Import posture |
| --- | --- | --- |
| `organizations` | Tenant boundary for all CRM data. | Must exist before any import. |
| `users` | Staff identities and assignees. | Import later unless a job assignment is already reviewed. |
| `organization_memberships` | User access to organizations. | Not part of data import. |
| `clients` | Canonical customer accounts. | Import first after alias review. |
| `contacts` | People linked to a client and optionally a site. | Import after clients; site links optional only when unresolved for review. |
| `sites` | Physical/service locations. | Must resolve to a canonical client before import. |
| `jobs` | Service work scoped to a client and site. | Must resolve to a canonical site and matching client. |
| `bmp_systems` | Stormwater assets at a site. | Import after sites when system identity is clear. |
| `observations` | Findings tied to a job and optionally a BMP system. | Import after jobs and systems. |
| `evidence_files` | Metadata for documents, photos, and Drive links. | Must attach to one clear client, site, job, system, or observation parent. |
| `reminders` | Local task/reminder records. | Import only when linked to one clear client, site, or job. |
| `email_import_batches` | Local batch metadata for email imports. | Provider import preview only; no mailbox crawl. |
| `email_messages` | Local email records. | May be linked or explicitly unlinked for review. |
| `email_record_links` | Reviewed links between emails and CRM records. | Must point to one clear client, site, or job. |
| `ai_drafts` | Review-first generated or local draft text. | Not imported blindly; attach only to reviewed context. |
| `reports` | Report snapshots and output file references. | Import later after jobs/files are clean. |
| `activity_log` | Local audit/activity timeline entries. | Generated by app workflows, not imported blindly. |
| `outlook_connections` | Server-side Outlook OAuth token metadata. | Never imported from CSV. |
| `external_record_ids` | Source-system identity map for imported records. | Required for duplicate prevention and re-runs. |
| `client_aliases` | Messy client names mapped to canonical clients. | Review before client/site import. |
| `site_aliases` | Messy site names, store numbers, and folder names mapped to sites. | Review before site/job/file import. |
| `service_catalog` | Canonical service codes and categories. | Seed/reference before jobs are imported. |
| `file_categories` | Canonical document/file classification. | Seed/reference before Drive links are imported. |
| `import_batches` | Dry-run batch summary for future V2 import center. | Created by future reviewed workflows only. |
| `import_rows` | Staged row-level validation results. | Never treated as committed CRM data. |

## 4. Import Order

1. Clients
2. Contacts
3. Sites
4. Jobs
5. BMP systems
6. Evidence files / Drive links
7. Reminders
8. Emails
9. Reports/photos later

Clients come before sites because no site may exist without a canonical client. Sites come before jobs because no job may exist without a canonical site. Jobs come before reports because report readiness depends on a real job scope, dates, evidence, and timeline. Files must attach to exactly one clear parent. Emails can remain unlinked for review, but they must not be silently lost or treated as linked without a reviewed target.

## 5. Required Import Rules

- Every import row must include `source_system` and a stable external or legacy ID.
- External IDs must be unique within `organization_id`, `source_system`, `source_table`, and `source_id`.
- Alias rows must be reviewed before they create or attach canonical clients/sites.
- Client aliases cannot create weak mappings from vague names alone.
- Site aliases may map store numbers, folder names, known location names, or legacy IDs, but must still resolve to a reviewed client or site.
- Sites with missing or unresolved clients are stop conditions.
- Jobs with missing or unresolved sites are stop conditions.
- Jobs with a client that does not match the resolved site client are stop conditions.
- Documents and Drive links with no parent or multiple parents are stop conditions.
- Emails with no parent must be explicitly marked unlinked for review.
- Provider OAuth tokens, mailbox contents, Drive folder crawls, private files, local DB files, and real customer spreadsheets must never be committed.

## 6. Entity Field Mapping

| Entity | Minimum identity fields | Minimum relationship fields | Notes |
| --- | --- | --- | --- |
| Client | `source_system`, `client_external_id`, `canonical_name` | `organization_id` at apply time | Alias values should map messy names to the canonical row. |
| Contact | `source_system`, `contact_external_id`, `name`, `email` | `client_external_id`, optional `site_external_id` | Contacts without a client should stay staged. |
| Site | `source_system`, `site_external_id`, `canonical_name` | `client_external_id` | Store numbers and folder names belong in `site_aliases`. |
| Job | `source_system`, `job_external_id`, `name`, `status` | `client_external_id`, `site_external_id` | Service names should resolve against `service_catalog` when available. |
| Document/File | `source_system`, `document_external_id`, `file_name`, `document_category` | Exactly one parent reference | Store only metadata/links until file sync is explicitly designed. |
| Email | `source_system`, `email_external_id`, `provider`, `subject`, `sender` | One parent reference or explicit unlinked review state | No provider calls during template validation. |

## 7. Stop Conditions

Stop the import path when any of these are present:

- Dirty working tree containing private/generated files.
- Tracked `.env`, `.env.local`, private CSV/XLSX, or local DB files.
- Missing required columns in any template.
- Missing source system or external IDs.
- Duplicate external IDs.
- Site rows with missing/unresolved clients.
- Job rows with missing/unresolved sites.
- Job rows whose client does not match the resolved site's client.
- Document rows with no parent, multiple parents, invalid parent type, or unresolved parent ID.
- Email rows that are neither linked nor explicitly unlinked.
- Invalid required email address, URL, or status values.

## 8. Dry-Run Review Checklist

- Confirm all row counts match the source files.
- Confirm duplicate rows are expected and intentionally skipped or cleaned.
- Confirm every site has one canonical client.
- Confirm every job has one canonical site and matching client.
- Confirm every document category maps to a real future `file_categories` code.
- Confirm every document/Drive link has exactly one reviewed parent.
- Confirm unlinked emails are intentionally unlinked and have a review reason.
- Confirm no real/private source files are staged or committed.
- Confirm validator output is saved only to ignored report paths when it contains private clues.

## 9. Future V2 Import Center

The future Import Center should read private source files locally, create an `import_batches` dry-run summary, stage each row in `import_rows`, show invalid/duplicate/unmatched rows for review, and only enable a commit step after all stop conditions are resolved.

The commit step should:

- Write canonical CRM rows only after reviewed mappings exist.
- Write `external_record_ids` for every committed row.
- Preserve row-level audit metadata.
- Never call Outlook, Gmail, Drive, or OpenAI during validation.
- Never create reports/photos automatically from imported rows.

## 10. What Must Never Be Imported Blindly

- Real Clients, Sites, Jobs, Documents, or Emails without validation.
- Sites without clients.
- Jobs without sites.
- Files without one clear parent.
- Client/site aliases created only from vague folder names.
- Provider credentials, OAuth tokens, API keys, or local `.env` files.
- Private CSV/XLSX workbooks or local DB files.
- Mailbox or Drive contents from an automated crawl.
- Report snapshots, photosheets, DOCX/PDF output, or V1 report layout data.
